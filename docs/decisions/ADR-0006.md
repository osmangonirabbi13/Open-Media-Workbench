# ADR-0006: FFmpeg Process Orchestration and Export Pipeline

**Status:** PROPOSED  
**Date:** 2026-10-13  
**Authors:** OpenTake Core Architecture Team  
**Deciders:** Lead Systems Architect, Media Pipeline Lead  
**Target Release:** v0.1.0 Beta  

---

## 1. Context & Problem Statement
Exporting an edited video requires compiling non-contiguous retained ranges into an FFmpeg render pipeline. We must decide how FFmpeg is invoked (managed child process vs C-FFI linking) and whether final exports mandate full re-encoding or attempt stream copying.

## 2. Decision Drivers
- Crash immunity: Corrupted frames must never segfault the desktop application.
- Licensing safety: Avoid in-process C-linkage that triggers GPL viral expansion into permissive crates.
- Frame accuracy: Cuts must occur exactly on user-specified frames without frozen or gray artifact frames.
- A/V synchronization across spliced segment joints.

## 3. Options Considered
- **Option 1 (Managed Child Process + Mandatory Re-Encoding via Complex Filtergraph):** Spawn FFmpeg CLI using typed argument arrays; compile EDL to normalized filtergraph (`trim`, `setpts`, `atrim`, `asetpts`, `concat`); encode via `libx264` + `aac`.
- **Option 2 (Stream Copying `-c copy` with Concat Demuxer):** Splice media without re-encoding.
- **Option 3 (In-Process C-FFI Linking via `ffmpeg-next`):** Link directly to `libavcodec` / `libavformat`.

## 4. Proposed Decision
Adopt **Option 1 (Managed Child Process + Mandatory Re-Encoding via Complex Filtergraph)**.

## 5. Consequences & Tradeoffs
- **Positive:** Complete isolation: an FFmpeg crash exits as an error result in Rust. Re-encoding guarantees 100% frame-accurate cut points. Normalized PTS prevents A/V desync.
- **Negative:** Re-encoding consumes CPU time and requires longer render times than stream copying.
- **Tradeoff Accepted:** Stream copy produces severe visual corruption (gray/frozen frames) when cutting between keyframes. Frame accuracy and reliability are mandatory for a production release.

## 6. Risk Assessment & Alternatives Rejected
- Option 2 was rejected because stream copy cannot cut between I-frames.
- Option 3 was rejected due to segfault crash hazards and GPL linking complexity.
