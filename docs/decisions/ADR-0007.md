# ADR-0007: Project Serialization and Recovery

**Status:** PROPOSED  
**Date:** 2026-10-13  
**Authors:** OpenTake Core Architecture Team  
**Deciders:** Lead Systems Architect, Persistence Lead  
**Target Release:** v0.1.0 Beta  

---

## 1. Context & Problem Statement
Projects must be saved, restored, and shared across directories. We must decide the persistence format (JSON vs SQLite) and implement crash-resilient file persistence that protects user work.

## 2. Decision Drivers
- Human-readability, inspectability, and ease of debugging.
- Crash-safety: Zero chance of corrupting an existing project on power loss or mid-write crash.
- Clean schema versioning (`schema_version: 1`) and backward compatibility.
- Separation of durable project edits from transient waveform caches.

## 3. Options Considered
- **Option 1 (Versioned JSON `.opentake` with Atomic Write-and-Rename):** Human-readable JSON; saved via write-to-temp-then-rename with `fsync`; backup file `.opentake.bak` preserved.
- **Option 2 (Embedded SQLite Database):** Store project edits and metadata inside an embedded SQLite `.db` file.
- **Option 3 (Binary Serialization via `bincode` / `protobuf`):** Packed binary representation.

## 4. Proposed Decision
Adopt **Option 1 (Versioned JSON `.opentake` with Atomic Write-and-Rename)**.

## 5. Consequences & Tradeoffs
- **Positive:** Projects can be opened and inspected in any text editor. Atomic swap guarantees zero truncated files. JSON serialization in Rust via `serde_json` is blazing fast for small documents.
- **Negative:** Slightly larger file size than binary format (a few kilobytes instead of a few hundred bytes).
- **Tradeoff Accepted:** A few kilobytes is negligible for modern storage, and human readability provides immense value for debugging and support.

## 6. Risk Assessment & Alternatives Rejected
- Option 2 was rejected as unnecessary overhead (database migrations, connection pooling, file locking) for a single-source linear rough-cut tool.
- Option 3 was rejected due to lack of inspectability.
