# ADR-0008: FFmpeg Licensing and Distribution Strategy

**Status:** PROPOSED  
**Date:** 2026-10-13  
**Authors:** OpenTake Core Architecture Team  
**Deciders:** Lead Systems Architect, Open-Source Governance Lead  
**Target Release:** v0.1.0 Beta  

---

## 1. Context & Problem Statement
The developer host system has FFmpeg 8.0.1 compiled with `--enable-gpl` and `--enable-libx264`. Distributing FFmpeg binaries bundled inside an installer triggers GNU GPL reciprocal source code distribution obligations. We must establish a legal, robust strategy for local development and beta distribution.

## 2. Decision Drivers
- Strict compliance with the GNU General Public License (GPL) and FFmpeg legal terms.
- High-quality, reliable H.264 video encoding (`libx264`) for end users.
- Frictionless local development experience on Linux without unnecessary dependency rebuilding.
- Reliable packaging for Windows, macOS, and Linux desktop installers.

## 3. Options Considered
- **Option 1 (Two-Stage Strategy: System FFmpeg during Development, GPL Sidecars for Windows/macOS + Package Dependencies for Linux):** Use host `/usr/bin/ffmpeg` during development; in release packaging, Linux `.deb` depends on system `ffmpeg`, while Windows/macOS bundles GPL sidecars with complete upstream source code attribution.
- **Option 2 (Strict LGPL-Only Bundling):** Disable all GPL components and strip `libx264`, attempting to use Cisco OpenH264 or native encoders.
- **Option 3 (Require Users to Manually Install FFmpeg on All Platforms):** Ship no binaries; force all users to configure their own PATH.

## 4. Proposed Decision
Adopt **Option 1 (Two-Stage Strategy)**.

## 5. Consequences & Tradeoffs
- **Positive:** Zero packaging friction during development (STEP 3–26). Delivers best-in-class `libx264` export quality. Aligns with OpenTake's proposed GPL-3.0 license.
- **Negative:** Windows and macOS release builders must include and host matching FFmpeg source code tarballs to satisfy GPL Section 6.
- **Tradeoff Accepted:** Standard practice among major open-source desktop editors (OBS Studio, HandBrake).

## 6. Risk Assessment & Alternatives Rejected
- Option 2 was rejected because stripping `libx264` severely degrades export encoding quality and reliability.
- Option 3 was rejected because forcing non-technical creators to install CLI tools destroys adoption.
