# ADR-0003: Tauri IPC and Security Model

**Status:** PROPOSED  
**Date:** 2026-10-13  
**Authors:** OpenTake Core Architecture Team  
**Deciders:** Lead Systems Architect, Security Lead  
**Target Release:** v0.1.0 Beta  

---

## 1. Context & Problem Statement
The frontend React application requires interaction with native media inspection, editing engines, and FFmpeg process management. Exposing unrestricted filesystem or shell execution APIs to the frontend creates severe security vulnerabilities and fragile race conditions.

## 2. Decision Drivers
- Principle of Least Privilege: Zero unrestricted shell execution (`shell:all` forbidden).
- High-frequency event throttling to prevent IPC saturation.
- Strongly typed request/response schemas matching Rust and TypeScript.
- Protection against stale events and frontend remount race conditions.

## 3. Options Considered
- **Option 1 (Granular Typed Commands + Throttled Async Events):** Explicit typed IPC commands via Serde structs; background progress emitted over Tauri events capped at 10 Hz.
- **Option 2 (Raw Dynamic JSON IPC):** Passing untyped `serde_json::Value` objects between React and Rust.
- **Option 3 (Direct File/Process Execution from Frontend):** Granting Tauri shell permissions directly to the frontend.

## 4. Proposed Decision
Adopt **Option 1 (Granular Typed Commands + Throttled Async Events)** with strict Tauri 2 capability files.

## 5. Consequences & Tradeoffs
- **Positive:** Neutralizes command injection vulnerabilities. Keeps frontend and backend state synchronized with compile-time type safety.
- **Negative:** Requires defining TypeScript interfaces matching Rust request/response structs.
- **Tradeoff Accepted:** Type definitions provide high reliability and prevent runtime serialization bugs.

## 6. Risk Assessment & Alternatives Rejected
- Option 3 was rejected as an unacceptable security vulnerability.
- Option 2 was rejected due to lack of type safety and high risk of subtle runtime bugs.

## 7. Outstanding Verification
- Validate Tauri 2 capability configuration in `src-tauri/capabilities/default.json` in STEP 3.
