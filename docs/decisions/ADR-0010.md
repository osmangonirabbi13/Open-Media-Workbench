# ADR-0010: Cross-Platform Release and Packaging Strategy

**Status:** PROPOSED  
**Date:** 2026-10-13  
**Authors:** OpenTake Core Architecture Team  
**Deciders:** Lead Systems Architect, Release Engineering Lead  
**Target Release:** v0.1.0 Beta  

---

## 1. Context & Problem Statement
OpenTake targets Windows, macOS, and Linux desktop environments, while the primary development machine is Linux x86_64. We must define the packaging formats, CI/CD pipeline, and code-signing approach for early beta distribution.

## 2. Decision Drivers
- Support for primary developer's Ubuntu Linux environment.
- Reproducible multi-platform builds using GitHub Actions.
- Pragmatic early-beta distribution for Windows and macOS without prohibitive upfront certificate costs.
- Transparent communication regarding unsigned binary warnings for community testers.

## 3. Options Considered
- **Option 1 (Linux-First Local Verification with Automated GitHub Actions CI Matrix for Windows/macOS):** Verify Linux builds locally; automate Windows NSIS and macOS DMG bundles via GitHub Actions; document SmartScreen and Gatekeeper bypass instructions for early beta testers.
- **Option 2 (Block Windows and macOS Releases Until Paid Certificates Acquired):** Restrict v0.1.0 Beta strictly to Linux.
- **Option 3 (Commercial Code Signing Upfront):** Purchase expensive Apple Developer accounts and Windows EV certificates before writing code.

## 4. Proposed Decision
Adopt **Option 1 (Linux-First Local Verification with Automated GitHub Actions CI Matrix for Windows/macOS)**.

## 5. Consequences & Tradeoffs
- **Positive:** Enables global multi-platform testing without financial barriers. Full local iteration velocity on Linux. Clear automated build pipeline in STEP 27.
- **Negative:** Windows testers will see an "Unknown Publisher" SmartScreen prompt; macOS testers must run `xattr -cr` or click "Open Anyway".
- **Tradeoff Accepted:** Standard industry procedure for open-source v0.1.0 beta releases.

## 6. Risk Assessment & Alternatives Rejected
- Option 2 was rejected because early cross-platform community feedback is vital.
- Option 3 was rejected as premature expenditure before beta validation.

## 7. Outstanding Verification
