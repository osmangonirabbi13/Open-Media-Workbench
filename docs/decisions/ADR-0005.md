# ADR-0005: Playback and Preview Proxy Strategy

**Status:** PROPOSED  
**Date:** 2026-10-13  
**Authors:** OpenTake Core Architecture Team  
**Deciders:** Lead Systems Architect, Desktop Lead  
**Target Release:** v0.1.0 Beta  

---

## 1. Context & Problem Statement
The video editor requires responsive, low-latency video scrubbing and real-time playback that skips cut regions. Platform WebViews have differing codec capabilities (e.g., Linux WebKitGTK with GStreamer vs Windows WebView2 vs macOS WKWebView).

## 2. Decision Drivers
- Instant video playback for primary reference formats (MP4 H.264/AAC).
- Universal playback fallback for unplayable or high-overhead formats (MKV/Opus, ProRes, HEVC).
- Low latency seeking during timeline scrubbing ($\le 150\text{ ms}$).
- Feasibility within the ~30-day single-developer development timeline.

## 3. Options Considered
- **Option 1 (Two-Tier Hybrid: Direct Native HTML5 `<video>` + Transcoded 720p H.264 Proxy Fallback):** Play compatible media directly via Tauri asset protocol; transcode unplayable media to lightweight 720p proxy on demand.
- **Option 2 (Universal Proxy for Every Media File):** Mandate proxy generation for all imported videos before previewing.
- **Option 3 (Custom Native Video Window via WGPU / libmpv):** Bypass WebView completely and embed a native video rendering window.

## 4. Proposed Decision
Adopt **Option 1 (Two-Tier Hybrid Strategy)**.

## 5. Consequences & Tradeoffs
- **Positive:** Zero wait time for 90% of standard MP4 imports. Guaranteed playback reliability on Linux via automatic 720p proxy fallback when WebKitGTK codecs are missing.
- **Negative:** Editing unplayable containers requires a brief initial proxy transcode pass ($< 15\text{ s}$ per 10 min).
- **Tradeoff Accepted:** Proxy generation is non-blocking and stores derived artifacts in temporary cache (`~/.cache/opentake/proxies/`). All final export decisions continue referencing the raw source file.

## 6. Risk Assessment & Alternatives Rejected
- Option 3 was rejected as it violates the 30-day timeline due to complex cross-platform window embedding issues.
- Option 2 was rejected because forcing proxy generation for every file destroys instant onboarding.
